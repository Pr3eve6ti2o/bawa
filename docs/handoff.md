# Bawa AI Wallet Builder — revised handoff (acceptance programme)

This is the revised final report for the Bawa AI Wallet Builder programme, Phases 0–10 plus the acceptance programme (2026-11-10). All implementation was authored by GPT-6-Astra (API 2, max reasoning), with first-hand verification by Orion. Orion then found, by first-hand clean-checkout verification, that the one-prompt workflow and the quality gates both assumed dependencies already installed (the acceptance lane's clean-checkout evidence had depended on manual npm ci steps); he hand-applied three small fixes per the same A-3 precedent — a CLI setup step in build-wallet.mjs, two setup gates in quality-gates.mjs, and the engine-setup ordering — and re-verified all 7 profiles plus 13/13 gates from a bare clone at 7b4990a. Those fixes are named in the table. All 20 local commits remain local; none has been pushed. The delivery is builder infrastructure, registries, instructions and Web/Android starters, not complete wallet applications. The checks below establish evidence within a stated scope; they do not remove the implementation gaps, outstanding review requirements or separate approval gates.

## What another AI can and cannot produce from Bawa today

**Can.** Give it one plain request — "Create a Web wallet", "Create an Android wallet", "Create a multi-chain wallet", "Create an HD wallet", "Create a Bitcoin wallet", "Create an EVM wallet", "Derive addresses only from extended public keys" — and `scripts/build-wallet.mjs` classifies it, generates a differentiated project for its profile into `generated/<profile-id>`, verifies that generated project, and writes a JSON report. All 7 requests were verified end-to-end from a fresh clone at `7b4990a` without manual installs (2026-11-10); see the Reproducibility row for the accepted clean-checkout run and evidence. The generated project states exactly what it is, what is implemented, what is missing, which chains it supports and its verification status. The instructions (`AGENTS.md`, `WALLET_BUILDER.md`, `ai/request-routing.md`, `ai/profiles/<id>.md`, registries) give the AI the exact resources, pins, derivation paths and boundaries to use.

**Cannot.** It cannot produce a complete wallet: no profile builds send, sign, broadcast, balances, prices or history, and no code for those exists. It cannot produce a mainnet-ready wallet: mainnet use is blocked on M-31/M-15 closure and separate approvals. It cannot produce on-device Android derivation (no AAR), a live-browser-verified Web wallet, a TON send path, or a GUI-verified TON withdrawal. It cannot mistake a starter for a complete wallet if it reads the generated README and the registry statuses — those state the limits explicitly.

## What this repo is not

- It is not a hosted wallet, custody service or exchange.
- It is not a complete Web or Android wallet application, and is **not production-ready, secure or audited**. Passing internal checks does not establish those properties.
- It is **not safe for real funds**. Do not use these starters to hold or move real funds.
