# Glossary

Reference. Terms are listed alphabetically in a single table.

| Term | Plain definition | Authority |
|---|---|---|
| **AAD** | Additional authenticated data for the AES-256-GCM encryption of the seed bundle. The repo's frozen legacy value is `nova-shop-seed-v1`; changing it breaks decryption of existing artefacts. | Supplied repo AAD evidence |
| **Account** | Use this term for the hardened `account'` level of the derivation path. Bawa exports an account-level public key at `m/purpose'/coin'/account'`, for example BTC `m/84'/0'/0'`. The daemon and one-shot tool derive receiving addresses below that account at `/0/<index>`. | BIP44; Bawa code |
| **Address index** | Read this as the final number in the derivation path. Count receiving or change addresses from `0`, according to the selected change branch. | BIP44 |
| **Air-gap** | Treat a signing device as air-gapped only if it never has a live data link to an internet-connected computer. Move the unsigned transaction and signed result by hand, using methods such as PSBT files on a MicroSD card or QR codes. In Coldcard's example, use Sparrow to export the unsigned file and broadcast the returned signed transaction, and perform on-screen review and signing on the Coldcard. | Coldcard MicroSD guide (vendor claim) |
| **App PIN** | Use this short numeric code to unlock the app. Do not confuse it with the vault unlock passphrase or the BIP-39 passphrase. | Bawa |
| **BIP** | Bitcoin Improvement Proposal: the numbered documents that specify Bitcoin standards (for example BIP-32, BIP-39, BIP-44). | BIP-32; BIP-39; BIP-44 |
| **BIP-39 passphrase** | Treat this as the optional input used alongside the mnemonic to derive the seed, not an extra word from the mnemonic word list. Changing it produces an entirely different seed. Keep it empty under Bawa's policy. | BIP39; Bawa policy |
| **Chain code** | Use this 32-byte value, produced alongside the master private key, with a parent key and an index to derive a child key. | BIP32 |
| **Chain ID** | An EVM network identifier, such as `11155111` for Sepolia, that distinguishes networks sharing an address format. | Supplied repo/corpus evidence (`e3b65fb0`) |
| **Change branch** | The `change` level of a derivation path: `0` for receiving addresses and `1` for change addresses. Bawa derives receiving addresses only and has no change-branch derivation. | BIP-44; supplied Bawa evidence |
| **Checksum** | A check value associated with a BIP-39 mnemonic, descriptor or address. The BIP-39 mnemonic checksum's bit length is the entropy bit length divided by 32. | BIP-39 (mnemonic); supplied corpus evidence (descriptors and addresses) |
| **Coin type** | The `coin_type'` level of the BIP-44 derivation path, using values assigned by SLIP-0044. The listed values are BTC `0`, ETH `60`, TRX `195` and TON `607`. | BIP-44; SLIP-0044 |
| **Confirmation** | An unconfirmed transaction has zero confirmations; on the active chain, its containing block counts as one and each subsequent block adds one. Trackers must handle reorganisations, which can reduce that count or remove the transaction from the active chain. | Bawa code |
| **Custody vs non-custody** | Recognise custody if another party can spend your funds or stop you spending them. For non-custody, require that you alone control enough signing power to spend without needing a provider's signature. For multisig and MPC, work out which parties control the required threshold rather than accepting the product's label. | Spending control and signing threshold |
| **Data key** | A random 32-byte key for decrypting `seed.enc.json`, shown once at creation and kept only in the reader's offline record. It is not derived from a passphrase. | `tools/hdwallet-gen/generate.js:144,146,187`; `tools/decrypt_seed.py:29` |
| **Derivation path** | Read this sequence of steps leading to a derived key as `m/purpose'/coin_type'/account'/change/address_index`. Treat purpose, coin type and account as hardened levels. Read `change` as `0` for receiving addresses and `1` for change addresses. | BIP44 |
| **Derivation policy** | The fixed set of derivation paths, passphrase rule and network a wallet uses. Bawa's policy is fixed per chain. | `RECOVERY.md`; supplied Bawa policy evidence |
| **Descriptor** | Use a Bitcoin Core output descriptor to express a script policy through forms such as pk, pkh, wpkh, sh, wsh, tr, multi and sortedmulti. Recognise that its key expressions can include a fingerprint, an origin path and a ranged derivation step, and that the descriptor may carry an eight-character checksum. Keep a descriptor backup to preserve the precise policy and rebuild the wallet's addresses without a seed. If it contains a private key, protect it like the key itself. | Bitcoin Core documentation; BIP-380 family |
| **Device credential** | Use the device's own unlock, such as a fingerprint or device PIN, as an app-unlock factor where the platform supports it. | Bawa |
| **EIP-1559** | The Ethereum fee-market upgrade in which transactions carry a maximum fee and priority fee instead of a single gas price. The Web draft's live proof used enveloped type 2 transactions. | Supplied repo/corpus evidence (`e3b65fb0`); Web draft live proof |
| **Entropy** | Use this term for the starting random data, 128 to 256 bits from a cryptographically secure random source. Before encoding it as words, BIP39 adds a checksum whose length in bits is the entropy length divided by 32. | BIP39 |
| **Extended key** | A BIP-32 representation of one key-tree node and its chain code, serialised into 78 bytes and then encoded with Base58Check. | BIP-32 |
| **Finality** | Treat a transaction as final when your settlement rule accepts it and no longer regards reversal as a practical concern. Apply a chosen confirmation count if your rule requires one, but do not treat the rule as a finality signal issued by the chain. On chains that allow reorgs, recognise that additional confirmations reduce risk but cannot make reversal mathematically impossible. | Settlement policy and reorg risk |
| **Fingerprint** | A short identifier taken from the first bytes of a key's hash, used to match a key or descriptor to its source. | Supplied corpus evidence |
| **Fixture** | A published test vector containing a mnemonic and expected addresses, used to verify derivation. It is eligible for comparison only when both implementations document the same standard, exact derivation path, chain, network and output format; a match supports that fixture only. | Docs/11, line 95 |
| **Gap limit** | The number of consecutive unused addresses after which a wallet stops scanning for used addresses. Recovery must scan both receiving and change branches; addresses beyond the gap can be missed. | BIP44 |
| **Hardened derivation** | Use the parent private key for this child-key derivation; a public key alone cannot derive hardened children. Recognise indices of 2³¹ and above as hardened. Read an apostrophe as marking a hardened index, as in `44'`. | BIP32 |
| **HD wallet** | A hierarchical deterministic wallet: one mnemonic derives a tree of keys. The guide covers a non-custodial HD wallet. | Supplied repo/corpus evidence (`e3b65fb0`) |
| **HSM** | Recognise a hardware security module (HSM) as a dedicated device or server module built to resist tampering and used by institutional custodians. Note that key generation, storage and signing happen inside it, without private keys leaving the module. | General security terminology |
| **Indexer** | A system that makes chain history searchable. It does not hold keys. | Bawa code |
| **Jetton** | A fungible token on TON. | Android guide; `docs/02` |
| **Keystore** | A file or system store holding encrypted key material. This general concept is distinct from Bawa's vault, which is its encrypted seed bundle. | Supplied repo/corpus evidence (`e3b65fb0`) |
| **Mainnet** | The production network of a chain, where transactions move real value. Mainnet is outside this guide's scope. | Guide scope |
| **Master key** | Use this term for the starting private key for BIP32 derivation. It is produced from the seed using HMAC-SHA512, together with a 32-byte chain code. | BIP32 |
| **Masterchain** | The TON chain that coordinates workchains. | Android guide; `docs/02` |
| **Mnemonic** | Use this term for a word sequence encoding the entropy and its checksum. Each 11-bit chunk selects a word from a 2,048-word list, producing 12, 15, 18, 21 or 24 words. | BIP39 |
| **MPC** | Distinguish multi-party computation (MPC) threshold signing from Shamir sharing: participants generate key shares together so the complete private key is never assembled in one place, and enough shares jointly produce a single ordinary on-chain signature rather than reconstructing the secret. Determine whether the wallet is self-custodial by checking who controls enough shares to meet the signing threshold. | Bitcoin.com MPC explainer (community research, not a specification) |
| **Multisig** | An m-of-n spending rule requires signatures from m of n distinct keys, preferably independently controlled. When restoring, you need all n public-key derivations plus the complete policy, including key ordering; signing keys alone do not restore the wallet. | [Trezor multisig guide](https://trezor.io/learn/a/multisig); [BitBox support hub](https://support.bitbox.swiss/) (both verified live 8 November 2026) |
| **Non-hardened derivation** | Use this term for child-key derivation using indices from 0 to 2³¹ − 1. Child public keys can be derived from the parent public key and its chain code. | BIP32 |
| **Nonce** | A random, one-time initialisation value for AES-256-GCM encryption. On EVM chains, the same name instead means a per-account transaction counter. | Supplied repo and corpus evidence |
| **Payment request** | A structured request containing an address plus optional amount, asset and network fields. A wallet can display it as a QR code or receive it by scanning. | Android guide: `P.renderAndVerifyQr` and engine payment-request parser |
| **PBKDF2** | A derivation method used for the seed and the Web vault's unlock key. Seed derivation uses PBKDF2-HMAC-SHA512 with 2,048 iterations; the Web vault uses PBKDF2 with 600,000 iterations and SHA-256. | Existing Seed entry; supplied Web vault evidence |
| **Private key** | A secret key that authorises signing; the master key is the starting BIP-32 private key. Keep private keys out of watch-only material. | BIP-32 |
| **PSBT** | A partially signed Bitcoin transaction: a binary structure with a global map and per-input/per-output maps carrying the UTXO details and derivation paths needed for offline signing. A PSBT moves through unsigned, partially signed and finalised states; only a finalised PSBT can be extracted and broadcast. Use a watch-only wallet to create the unsigned package, then finalise and broadcast it after a separate hardware wallet or offline signer adds signatures. Before authorising a signature, check the recipient, payment amount and change address on the signing device's own display. | BIP-174; BIP-371 for Taproot |
| **Public key** | The public half of a key pair, derived from the private key. It identifies the key holder for verification and address derivation without authorising spending. | BIP-32 |
| **Purpose** | The first level after `m` in the BIP-44 derivation path, written `purpose'` and followed by `coin_type'`. | BIP-44 |
| **QR code** | A machine-readable encoding of an address or payment request for display or camera scanning. Receive-QR is in scope; it remains unimplemented in the evidence recorded on 2026-11-08. | Android guide; Web guide; repo `docs/13–14` |
| **Recovery phrase** | Use **Mnemonic** instead of this deprecated term. | Bawa |
| **Reorg** | Recognise a reorg as a chain reorganisation that replaces recent blocks, and allow for a transaction that looked confirmed to drop out as a result. | Bawa code |
| **RPC** | A remote procedure call to a node or provider that reads chain state, such as balances, history or transaction status. It does not hold keys. | Bawa code |
| **Seed** | Derive this 64-byte value from the mnemonic and optional BIP-39 passphrase. NFKD-normalise both inputs before applying PBKDF2-HMAC-SHA512 with 2,048 iterations. Use the literal text `mnemonic` followed by the normalised BIP-39 passphrase as the salt. BIP32 uses the seed to derive the master private key and chain code. | BIP39; BIP32 |
| **Seed bundle** | Use this term for `seed.enc.json`, the encrypted bundle file holding the seed, protected by a separate 32-byte data key. | Bawa |
| **Seed phrase** | Use **Mnemonic** instead of this deprecated term. | Bawa |
| **SegWit** | Segregated Witness: the Bitcoin upgrade that moves signature data out of the transaction body. Native SegWit in this guide uses bech32 addresses (`bc1q…` on mainnet, `tb1q…` on testnet), BIP-84 paths and `zpub`/`vpub` extended keys. | Supplied repo/corpus evidence (`e3b65fb0`); BIP-84 for paths |
| **Seqno** | A TON wallet's sequence number, used for replay protection. | Android guide; `docs/02` |
| **Shamir backup (SLIP-39)** | Use Shamir sharing to divide a master secret into backup shares: recover the secret by meeting the threshold, and recognise that any smaller set reveals nothing about it. Expect SLIP-39 to represent each share with 20 words for a 128-bit secret or 33 words for a 256-bit secret, using a 1,024-word list and an RS1024 checksum. Do not use these backups interchangeably with BIP-39. Distinguish their preservation of one secret for recovery from multisig's use of several independent keys for spending. | [SLIP-0039 specification](https://github.com/satoshilabs/slips/blob/master/slip-0039.md) (Final, verified live 8 November 2026) |
| **SLIP** | SatoshiLabs Improvement Proposal: the numbered documents that specify wallet standards such as coin-type assignments (SLIP-0044) and extended-key version bytes (SLIP-0132). | SLIP-0044; SLIP-0132 |
| **Subwallet (wallet ID)** | A TON wallet identifier, also called a wallet ID, that distinguishes multiple wallets derived from one key. The verified fixture uses 698983191. | Android guide; `docs/02`; verified TON fixture |
| **Taproot** | The Bitcoin upgrade adding Schnorr signatures and key-path or script-path spending. Bawa does not implement Taproot signing. | BIP-340/341/342; `docs/02`; `docs/09` |
| **Testnet** | A test network that mimics a mainnet chain for development and testing, using valueless test coins. This guide uses Bitcoin testnet4, Ethereum Sepolia, TRON Nile and TON testnet. | Guide scope |
| **Threshold** | In multisig, it is the `m` in an `m`-of-`n` spending rule. In MPC, it is the number of shares that must co-operate to sign. | Supplied multisig and MPC evidence |
| **Token identity** | A token's identity is its network together with its canonical contract or asset identifier. Decimals specify amount scaling, and a symbol alone is not a unique identifier. | Bawa code |
| **tpub** | A Bitcoin testnet extended public key in BIP32 format, with version bytes `0x043587cf`. Its registered path prefix is `m/44'/1'`. | BIP32; SLIP-0132; BIP44 (path convention) |
| **UTXO** | An unspent transaction output. A Bitcoin wallet's balance is the set of unspent outputs it can spend, rather than an account balance. | `docs/02`; `docs/09`; Android guide |
| **Vault** | Use this term for the encrypted store holding the seed bundle. | Bawa |
| **Vault unlock passphrase** | Use this passphrase to unlock the encrypted vault. Do not confuse it with the BIP-39 passphrase. | Bawa |
| **vpub** | A Bitcoin testnet extended public key in BIP32 format, with version bytes `0x045f1cf6`, registered for native SegWit (P2WPKH). Its registered path prefix is `m/84'/1'`. | BIP32; SLIP-0132; BIP84 |
| **Wallet** | Use this term for the application, not the mnemonic, the seed or the vault. | Bawa |
| **Watch-only** | A system holding only public material, such as xpubs, zpubs or addresses. It can derive and watch addresses but cannot spend. Bawa's `tools/hdwallet-gen` supports watch-only derivation for `btc`, `eth` and `trx` only. | Bawa code |
| **Workchain** | TON's chain identifier; `0` identifies the base workchain. | Android guide; `docs/02`; verified TON fixture |
| **xprv** | A Bitcoin mainnet extended private key in BIP32 format, with version bytes `0x0488ade4`. The registry associates this serialisation with P2PKH or P2SH and path prefix `m/44'/0'`. Bawa's daemon rejects private extended keys. | BIP32; SLIP-0132; BIP44 (path convention) |
| **xpub** | A Bitcoin mainnet extended public key in BIP32 format, with version bytes `0x0488b21e`. The registry associates this serialisation with P2PKH or P2SH and path prefix `m/44'/0'`. It can derive descendant public keys only through an uninterrupted sequence of non-hardened steps; it cannot sign, derive hardened children or derive private keys. An xpub alone does not uniquely specify an address format. Treat an xpub as sensitive public material: exposing it discloses addresses, balances, payment history and relationships. Never store an xpub alongside a child private key: that combination can expose the parent. | BIP32; SLIP-0132; BIP44 (path convention) |
| **ypub** | A Bitcoin mainnet extended public key in BIP32 format, with version bytes `0x049d7cb2`, registered for nested SegWit (P2WPKH in P2SH). Its registered path prefix is `m/49'/0'`. | BIP32; SLIP-0132; BIP49 |
| **zpub** | A Bitcoin mainnet extended public key in BIP32 format, with version bytes `0x04b24746`, registered for native SegWit (P2WPKH). Its registered path prefix is `m/84'/0'`. | BIP32; SLIP-0132; BIP84 |
